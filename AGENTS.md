# Collaboration workflow

- For exploratory changes, diagnose the problem and present the proposed solution before editing files or running builds, tests, linters, formatters, or other validation commands.
- Wait for the user's explicit approval (for example, "pode", "aceito", or "concordo") before implementing the proposal. A direct implementation request counts as approval for that requested scope.
- After implementation, stop and let the user review the result. Do not run builds, tests, linters, formatters, or any other validation until the user explicitly confirms that the changes look good and approves the validation step.
- After that separate approval, run proportionate validation and autonomously fix issues found within the approved scope.
